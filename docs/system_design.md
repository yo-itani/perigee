# 1on1システム 設計書

> イベントストーミング・画面設計をもとにまとめた実装前設計書。
> 最終更新：2026年4月

---

## 1. プロジェクト概要

1on1を管理するシステム。誰でもオーガナイザー（1on1の設定者）にもカウンターパート（1on1の相手方）にもなれる、固定ロールを持たない設計。スケジューリング・記録・共有・フォローアップまでの一連の流れをサポートする。Slack通知を中心としたコミュニケーション連携を含む。

### スコープ（初期実装対象）

- 定期1on1管理
- アドホック（突発）相談型の1on1
- アジェンダ・事前コメント管理
- 記録（メモ）・アクションアイテム管理
- Slack通知連携
- 記録の公開・閲覧・コメント機能
- ダッシュボード（共通）

### スコープ外（後回し）

- ユーザー登録・ペア管理（初期は固定データで対応）
- 認証・権限管理の詳細実装
- 1on1履歴の一覧・参照画面
- マネージャーによる過去履歴閲覧権限

## 2. ユビキタス言語

| 用語 | 説明 |
|---|---|
| **1on1** | オーガナイザーとカウンターパートが実施するミーティング。「セッション」とは呼ばない |
| **オーガナイザー（Organizer）** | 1on1を設定・記録・公開する主体。誰でもオーガナイザーになれる |
| **カウンターパート（Counterpart）** | 1on1の相手方。アジェンダ追加・コメント・アクションアイテム完了を行う |
| **マネージャー（Manager）** | 組織上の管理者。カウンターパートの過去1on1履歴を閲覧できる（後回し機能） |
| **アジェンダ** | 1on1で話す予定のトピック一覧 |
| **テンプレートアジェンダ** | 定期1on1の雛形アジェンダ。各カウンターパートの1on1に展開される |
| **アクションアイテム** | 1on1で決まったタスク。1on1ではなく「人（カウンターパート）」に紐づく |
| **記録（メモ）** | オーガナイザーが1on1中・直後に書く内容 |
| **下書き** | 公開前の状態。オーガナイザーのみ閲覧可 |
| **公開** | 記録をカウンターパートや他の閲覧者に見せる操作 |
| **閲覧者** | オーガナイザーが任意で追加した公開先ユーザー |
| **デフォルト公開先** | 1on1ペアごとにオーガナイザーが設定する公開先の既定値 |

## 3. ドメイン設計

### 3.1 境界コンテキスト

```
スケジューリング → 準備 → 実施・記録 → 公開管理
                                          ↓
                    通知（Slack）← 各フェーズのイベントをトリガーに送信

参照（リードモデル）← 全フェーズの結果を蓄積
設定 ← ユーザーごとの通知設定・デフォルト公開先
```

### 3.2 登場するアクター

| アクター | 役割 |
|---|---|
| **オーガナイザー** | 1on1を設定・記録・公開する主体 |
| **カウンターパート** | アジェンダ追加・コメント・アクションアイテム完了を行う |
| **閲覧者** | オーガナイザーが公開した記録を読み・コメントできる |
| **マネージャー** | カウンターパートの過去1on1履歴を閲覧できる（後回し） |
| **システム** | Slack通知などの自動処理 |

### 3.3 コンテキスト間連携（イベントフロー）

| イベント | 発行元 | 消費先 | 説明 |
|---|---|---|---|
| OneOnOneScheduled | スケジューリング | 通知 | 1on1が設定された時にSlack通知を送信 |
| OneOnOneStarted | 実施・記録 | 参照 | 1on1の開始を記録し、リードモデルを更新 |
| RecordPublished | 公開管理 | 通知 | 記録が公開された時にSlack通知を送信 |
| CommentAdded | 準備, 公開管理 | 通知 | コメント追加時にSlack通知を送信 |
| ActionItemCompleted | フォローアップ | 参照 | アクションアイテム完了をリードモデルに反映 |

#### コード例（ドメインイベント）

```python
@dataclass(frozen=True)
class OneOnOneScheduled:
    one_on_one_id: OneOnOneId
    organizer_id: UserId
    counterpart_id: UserId
    scheduled_at: datetime

@dataclass(frozen=True)
class RecordPublished:
    record_id: RecordId
    one_on_one_id: OneOnOneId
    published_by: UserId
    published_at: datetime
```

## 4. 1on1の2パターン

1on1の開始方法は2パターンあるが、**開始後（実施・記録・公開）の流れは共通**。

### パターンA：定期スケジュール型

- オーガナイザーが複数カウンターパートに対し設定
- **カウンターパートごとに個別の日時・繰り返しを設定**（1対多の構造）
- テンプレートアジェンダを全カウンターパートに展開
- カウンターパートはそれぞれの1on1でアジェンダを追加できる

作成起点（3種類）：
1. 新規で作成
2. テンプレートから作成（保存済みテンプレートを参照）
3. 過去の1on1からコピー（履歴を参照）

### パターンB：アドホック相談型

- カウンターパートが相談リクエストを送る
- 日時は**必須**（仮押さえとして登録。オーガナイザー承認で確定）
- カウンターパートがアジェンダを持ち込む

## 5. ドメインイベント一覧

### スケジューリング
- 定期1on1が設定された
- テンプレートアジェンダが作成された
- カウンターパートに展開された
- 相談リクエストが送られた
- オーガナイザーが受け付けた
- 1on1の日時が変更された（オーガナイザー・カウンターパートどちらでも）
- 1on1がキャンセルされた（オーガナイザー・カウンターパートどちらでも）
- テンプレートが保存された

### 準備（1on1前）
- アジェンダが追加された（オーガナイザー・カウンターパートどちらでも）
- アジェンダにコメントが追加された（オーガナイザー・カウンターパートどちらでも）
- アジェンダが削除された

### 実施・記録（1on1中〜直後）
- 1on1が開始された
- アジェンダが確認済みになった（チェック）
- メモが記録された（オーガナイザー）
- アクションアイテムが登録された（オーガナイザー）
- 記録が下書き保存された

### 公開管理
- 記録が公開された（→ Slack通知トリガー）
- 実際の公開先が変更された
- コメントが追加された（→ Slack通知トリガー）
- デフォルト公開先が設定された（オーガナイザー）

### 通知（Slack）
- スケジュール通知が送信された（1on1設定時）
- リマインドが送信された（設定時間前・ユーザーごとの設定参照）
- 公開通知が送信された（記録公開時）
- 変更通知が送信された（日時変更・キャンセル時）
- コメント通知が送信された（アジェンダコメント・記録コメント追加時）

### フォローアップ
- アクションアイテムが完了した（カウンターパート）
- 振り返りが記録された（オーガナイザー・カウンターパートどちらでも）

### 設定
- 通知設定が更新された（ユーザーごと）

## 6. リードモデル（参照系）

| リードモデル | 内容 | 主な用途 |
|---|---|---|
| 1on1履歴一覧 | 人ごと・時系列。マネージャー閲覧可（後回し） | 過去を振り返る・コピー作成の参照元 |
| 未完了アクションアイテム一覧 | 人（カウンターパート）に紐づく | 1on1開始時に「確認しますか？」として表示 |
| 前回の1on1サマリー | ペアごと | 次回アジェンダ作成時の参照 |
| テンプレート一覧 | オーガナイザーごと | テンプレートから1on1作成時の参照 |
| 公開範囲 | ログごと | カウンターパートが「誰に見えているか」確認するため |

## 7. ビジネスルール

### アクションアイテム
- アクションアイテムは**1on1ではなくカウンターパート（人）に紐づく**
- 1on1開始時に未完了アクションアイテムを表示するが、**アジェンダへの追加は任意（強制しない）**
- 定期1on1でもアドホック1on1でも同じ仕組みで動く

### アジェンダ
- オーガナイザー・カウンターパート**どちらでも**追加・削除・コメント可能
- 誰が追加したかのタグを表示（テンプレート / オーガナイザーが追加 / カウンターパートが追加）
- **全アジェンダにコメントを追加できる**（制限なし）
- コメントは全員に公開（非公開コメントなし）

### 公開先
- **オーガナイザーが設定する**（カウンターパートは変更できない）
- 2層構造：
  - **デフォルト公開先**（ユーザー設定 / 1on1ペアごと / オーガナイザーが設定）
  - **実際の公開先**（1on1ログごと / デフォルトを引き継ぎ / オーガナイザーが変更可能）
- **カウンターパートは誰に公開されているかを確認できる**（変更はできない）
- カウンターパート本人には常に公開
- 記録は**公開後にはじめてカウンターパート・閲覧者に見える**（下書き中はオーガナイザーのみ）

### 通知（Slack）
- リマインド時間はユーザーごとに設定可能
- コメントが追加されたら通知（アジェンダコメント・記録コメントどちらも）
- 下書き保存時は通知しない。公開時のみ通知する

### 日時変更・キャンセル
- オーガナイザー・カウンターパート**どちらでも**変更・キャンセル可能
- 変更・キャンセル時はSlack通知を送信
