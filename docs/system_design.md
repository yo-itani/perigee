# 1on1システム 設計書

> イベントストーミング・画面設計をもとにまとめた実装前設計書。
> 最終更新：2026年4月

---

## 1. プロジェクト概要

上司と部下の1on1を管理するシステム。スケジューリング・記録・共有・フォローアップまでの一連の流れをサポートする。Slack通知を中心としたコミュニケーション連携を含む。

### スコープ（初期実装対象）

- 上司と部下の定期1on1管理
- アドホック（突発）相談型の1on1
- アジェンダ・事前コメント管理
- 記録（メモ）・アクションアイテム管理
- Slack通知連携
- 記録の公開・閲覧・コメント機能
- ダッシュボード（上司・部下それぞれ）

### スコープ外（後回し）

- ユーザー登録・上司部下ペアの管理（初期は固定データで対応）
- 認証・権限管理の詳細実装
- 1on1履歴の一覧・参照画面

## 2. ユビキタス言語

| 用語 | 説明 |
|---|---|
| **1on1** | 上司と部下が実施するミーティング。「セッション」とは呼ばない |
| **アジェンダ** | 1on1で話す予定のトピック一覧 |
| **テンプレートアジェンダ** | 定期1on1の雛形アジェンダ。各メンバーの1on1に展開される |
| **アクションアイテム** | 1on1で決まったタスク。1on1ではなく「人（部下）」に紐づく |
| **記録（メモ）** | 上司が1on1中・直後に書く内容 |
| **下書き** | 公開前の状態。上司のみ閲覧可 |
| **公開** | 記録を部下や他の閲覧者に見せる操作 |
| **閲覧者** | 上司が任意で追加した公開先ユーザー（上の上司・人事など） |
| **デフォルト公開先** | 1on1ペアごとに上司が設定する公開先の既定値 |

## 3. ドメイン設計

### 3.1 境界コンテキスト

```
スケジューリング → 準備 → 実施・記録 → 公開管理
                                          ↓
                    通知（Slack）← 各フェーズのイベントをトリガーに送信
                    
参照（リードモデル）← 全フェーズの結果を蓄積
設定 ← ユーザーごとの通知設定・デフォルト公開先
```

### 3.2 登場するアクター

| アクター | 役割 |
|---|---|
| **上司** | 1on1を設定・記録・公開する主体 |
| **部下** | アジェンダ追加・コメント・アクションアイテム完了を行う |
| **閲覧者** | 上司が公開した記録を読み・コメントできる（上の上司・人事など）|
| **システム** | Slack通知などの自動処理 |

## 4. 1on1の2パターン

1on1の開始方法は2パターンあるが、**開始後（実施・記録・公開）の流れは共通**。

### パターンA：定期スケジュール型

- 上司が複数メンバーに対し設定
- **メンバーごとに個別の日時・繰り返しを設定**（1対多の構造）
- テンプレートアジェンダを全メンバーに展開
- 部下はそれぞれの1on1でアジェンダを追加できる

作成起点（3種類）：
1. 新規で作成
2. テンプレートから作成（保存済みテンプレートを参照）
3. 過去の1on1からコピー（履歴を参照）

### パターンB：アドホック相談型

- 部下が相談リクエストを送る
- 日時は**必須**（仮押さえとして登録。上司承認で確定）
- 部下がアジェンダを持ち込む

## 5. ドメインイベント一覧

### スケジューリング
- 定期1on1が設定された
- テンプレートアジェンダが作成された
- メンバーに展開された
- 相談リクエストが送られた
- 上司が受け付けた
- 1on1の日時が変更された（上司・部下どちらでも）
- 1on1がキャンセルされた（上司・部下どちらでも）
- テンプレートが保存された

### 準備（1on1前）
- アジェンダが追加された（上司・部下どちらでも）
- アジェンダにコメントが追加された（上司・部下どちらでも）
- アジェンダが削除された

### 実施・記録（1on1中〜直後）
- 1on1が開始された
- アジェンダが確認済みになった（チェック）
- メモが記録された（上司）
- アクションアイテムが登録された（上司）
- 記録が下書き保存された

### 公開管理
- 記録が公開された（→ Slack通知トリガー）
- 公開先が変更された
- コメントが追加された（→ Slack通知トリガー）
- デフォルト公開先が設定された（上司）

### 通知（Slack）
- スケジュール通知が送信された（1on1設定時）
- リマインドが送信された（設定時間前・ユーザーごとの設定参照）
- 公開通知が送信された（記録公開時）
- 変更通知が送信された（日時変更・キャンセル時）
- コメント通知が送信された（アジェンダコメント・記録コメント追加時）

### フォローアップ
- アクションアイテムが完了した（部下）
- 振り返りが記録された（上司・部下どちらでも）

### 設定
- 通知設定が更新された（上司・部下それぞれ）

## 6. リードモデル（参照系）

| リードモデル | 内容 | 主な用途 |
|---|---|---|
| 1on1履歴一覧 | 人ごと・時系列 | 過去を振り返る・コピー作成の参照元 |
| 未完了アクションアイテム一覧 | 人（部下）に紐づく | 1on1開始時に「確認しますか？」として表示 |
| 前回の1on1サマリー | ペアごと | 次回アジェンダ作成時の参照 |
| テンプレート一覧 | 上司ごと | テンプレートから1on1作成時の参照 |
| 公開範囲 | ログごと | 部下が「誰に見えているか」確認するため |

## 7. ビジネスルール

### アクションアイテム
- アクションアイテムは**1on1ではなく部下（人）に紐づく**
- 1on1開始時に未完了アクションアイテムを表示するが、**アジェンダへの追加は任意（強制しない）**
- 定期1on1でもアドホック1on1でも同じ仕組みで動く

### アジェンダ
- 上司・部下**どちらでも**追加・削除・コメント可能
- 誰が追加したかのタグを表示（テンプレート / 上司が追加 / 部下が追加）
- **全アジェンダにコメントを追加できる**（制限なし）
- コメントは全員に公開（非公開コメントなし）

### 公開先
- **上司が設定する**（部下は変更できない）
- 2層構造：
  - **デフォルト公開先**（ユーザー設定 / 1on1ペアごと / 上司が設定）
  - **実際の公開先**（1on1ログごと / デフォルトを引き継ぎ / 上司が変更可能）
- **部下は誰に公開されているかを確認できる**（変更はできない）
- 部下本人には常に公開
- 記録は**公開後にはじめて部下・閲覧者に見える**（下書き中は上司のみ）

### 通知（Slack）
- リマインド時間はユーザーごとに設定可能
- コメントが追加されたら通知（アジェンダコメント・記録コメントどちらも）
- 下書き保存時は通知しない。公開時のみ通知する

### 日時変更・キャンセル
- 上司・部下**どちらでも**変更・キャンセル可能
- 変更・キャンセル時はSlack通知を送信

## 8. 画面一覧

| 画面 | 主なアクター | 概要 |
|---|---|---|
| ダッシュボード（上司） | 上司 | 直近1on1・下書き未公開・全メンバーのAI一覧 |
| ダッシュボード（部下） | 部下 | 次の1on1・自分のAI・未読記録 |
| 1on1設定画面 | 上司・部下 | 定期型（メンバーごとの日時設定）/ アドホック型 |
| 1on1準備画面 | 上司・部下 | アジェンダ追加・コメント・未完了AI確認 |
| 1on1実施・記録画面 | 上司（主）・部下 | アジェンダチェック・メモ・AI登録 |
| 公開フロー | 上司 | 下書き → 公開先選択 → 公開 |
| 記録閲覧・コメント画面 | 上司・部下・閲覧者 | 記録閲覧・コメント（役割により表示が異なる） |

### 画面ごとの権限

| 機能 | 上司 | 部下 | 閲覧者 |
|---|---|---|---|
| 記録の編集 | ✅ | ❌ | ❌ |
| 公開先の変更 | ✅ | ❌ | ❌ |
| 公開先の確認 | ✅ | ✅ | ❌ |
| アジェンダの追加・削除 | ✅ | ✅ | ❌ |
| アジェンダへのコメント | ✅ | ✅ | ❌ |
| 記録へのコメント | ✅ | ✅ | ✅ |
| 日時変更・キャンセル | ✅ | ✅ | ❌ |
| アクションアイテムの完了 | ❌ | ✅ | ❌ |

## 9. 画面遷移

```
Slack通知（リンク）
    ↓
[準備画面]
    ↓ 「1on1を開始する」
[実施・記録画面]
    ↓ 「完了として保存」
[公開フロー（モーダル）]
    ├── 下書き保存 → 記録は非公開のまま
    └── 公開 → Slack通知送信 → 部下・閲覧者が[記録閲覧・コメント画面]へ
```
